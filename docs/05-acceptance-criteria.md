# Критерии приемки

## AC 01 Создание валидной заявки

**Дано** аутентифицированный житель и корректное тело запроса.  
**Когда** клиент отправляет новый `Idempotency-Key`.  
**Тогда** API возвращает `201`, заявка имеет статус `CREATED`, а история и outbox-событие содержат одну новую запись.

## AC 02 Безопасный повтор

**Дано** ранее успешно обработанный ключ и неизмененное тело.  
**Когда** клиент повторяет запрос.  
**Тогда** API возвращает тот же бизнес-результат, а количество заявок не увеличивается.

## AC 03 Повтор ключа с другим телом

**Дано** ранее использованный ключ.  
**Когда** клиент отправляет с ним другое тело.  
**Тогда** API возвращает `409 IDEMPOTENCY_KEY_REUSED`, данные не изменяются.

## AC 04 Валидация обязательных полей

**Дано** отсутствующая категория или описание из пробелов.  
**Когда** клиент создает заявку.  
**Тогда** API возвращает `422 VALIDATION_ERROR` и указывает проблемное поле.

## AC 05 Аварийный приоритет

**Дано** `is_emergency = true`.  
**Когда** заявка создается.  
**Тогда** сохраненный приоритет равен `critical`.

## AC 06 Конкурентное изменение

**Дано** версия заявки равна `4`.  
**Когда** клиент отправляет изменение с `If-Match: 3`.  
**Тогда** API возвращает `409 VERSION_CONFLICT`, статус и версия не меняются.

## AC 07 Допустимый переход

**Дано** назначенная заявка в статусе `ASSIGNED`.  
**Когда** назначенный мастер переводит ее в `IN_PROGRESS`.  
**Тогда** статус меняется, версия увеличивается на один, история и outbox обновляются.

## AC 08 Недопустимый переход

**Дано** заявка в статусе `CREATED`.  
**Когда** пользователь пытается перевести ее сразу в `COMPLETED`.  
**Тогда** API возвращает `409 INVALID_STATUS_TRANSITION`, данные не меняются.

## AC 09 Сбой уведомлений

**Дано** бизнес-операция зафиксирована, а сервис уведомлений недоступен.  
**Когда** worker не доставляет событие.  
**Тогда** заявка остается сохраненной, событие получает повтор с backoff, а после лимита переходит в `FAILED` и создает сигнал мониторинга.

## AC 10 Поиск и пагинация

**Дано** более одной страницы заявок.  
**Когда** диспетчер запрашивает фильтр по статусу и приоритету.  
**Тогда** API возвращает только подходящие записи, стабильную сортировку и метаданные страницы.
