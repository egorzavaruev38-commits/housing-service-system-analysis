# Бизнес правила

- **BRULE-01.** `external_request_id` уникален в пределах источника.
- **BRULE-02.** Один `Idempotency-Key` относится к одному телу запроса. Повтор с другим телом — конфликт.
- **BRULE-03.** Пустые строки и строки из пробелов не считаются заполненными значениями.
- **BRULE-04.** Допустимые приоритеты: `low`, `medium`, `high`, `critical`.
- **BRULE-05.** Допустимые статусы: `CREATED`, `ASSIGNED`, `IN_PROGRESS`, `COMPLETED`, `CANCELLED`, `REJECTED`.
- **BRULE-06.** Назначить можно только активного мастера.
- **BRULE-07.** Перевод в `ASSIGNED` требует назначенного мастера.
- **BRULE-08.** Перевод в `COMPLETED` возможен только из `IN_PROGRESS`.
- **BRULE-09.** Терминальные статусы `COMPLETED`, `CANCELLED`, `REJECTED` не меняются через обычный API.
- **BRULE-10.** Клиент передает ожидаемую версию заявки; несовпадение версии возвращает `409`.
- **BRULE-11.** Аварийная заявка создается с приоритетом `critical`.
- **BRULE-12.** Квартира, этаж и предпочтительное время могут отсутствовать для заявки по общей территории.
- **BRULE-13.** Каждый успешный переход статуса создает запись истории.
- **BRULE-14.** После бизнес-транзакции уведомление доставляется асинхронно и может быть повторено.

## Матрица переходов

| Текущий статус | Допустимый следующий статус |
|---|---|
| `CREATED` | `ASSIGNED`, `CANCELLED`, `REJECTED` |
| `ASSIGNED` | `CREATED`, `IN_PROGRESS`, `CANCELLED` |
| `IN_PROGRESS` | `ASSIGNED`, `COMPLETED`, `CANCELLED` |
| `COMPLETED` | Нет |
| `CANCELLED` | Нет |
| `REJECTED` | Нет |

Возврат `ASSIGNED → CREATED` означает снятие назначения. Возврат `IN_PROGRESS → ASSIGNED` означает передачу незавершенной работы другому мастеру и требует комментария.
